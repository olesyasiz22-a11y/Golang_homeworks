## Задание С3 №1
Реализована функция **AnalyzeSales**. Она принимает срез с информацией обо всех произошедших продажах, после выполнения возвращает отчет
со статистикой. Исходный срез не изменяется.
```go
func AnalyzeSales(sales []Sale) Report
```

На входе необходимо предоставить следующие данные:
- наименование товара (Product)
- категория товара (Category)
- сколько было продано данного товара в единицах (Quantity)
- стоимость единицы товара в копейках (UnitPriceKopecks)
- отменен товар (true) или нет (false) (Cancelled)

В отчете выводится информация про:
- общий доход от продаж в копейках (RevenueKopecks)
- общее количество проданного товара в единицах (UnitsSold)
- общий доход для каждой категории товара в копейках (RevenueByCategory)
- наиболее покупаемый продукт (TopProduct)
- количество некорректных записей о товарах (InvalidSales)

### Реализованный алгоритм 
1) Сначала формируется пустая запись будущего отчета, которая сможет вернуть интерпретируемый ответ (нули и пустые списки) для пустого входа.
2) Один раз производится полный проход по всем переданным на входе данным. Для каждой записи определяется:
- отменена ли она (если да, то данная запись не учитывается и мы переходим к следующей)
- корректны ли введенные для записи данные (указаны ли имя и категория, положительны ли количество и цена). Если они некорректны, запись фиксируется в поле некорректных и не обрабатывается для остальных полей отчета.
- если первые два этапа пройдены, сумма дохода от данного товара и его количество добавляются в общую статистику.
- также делается запись в доход по категории, фиксируется количество данного товара для будущего выявления топ-товара по количеству.
На данном этапе все поля финального отчета, кроме одного (TopProduct), уже заполнены полностью.
3) Мы один раз проходимся по списку всех уникальных товаров и финального количества продаж для каждого из них, через сравнение выявляя самый покупаемый товар. В случае наличия двух товаров с одинаковым количеством лидером становится лексикографически меньшее название товара.
4) Финально функция возвращает заполненную структуру, которую можно присвоить в переменную и использовать дальше.

### Сложность алгоритма
- **Время** - O(n). O(n) в первом цикле, где n - количество элементов в sales. O(n) в худшем случае для второго цикла, где мы проходимся по m - количество уникальных товаров, если у нас каждая запись в sales представляет собой уникальный товар и нет ни одного повторяющегося (m = n). Итоговая сложность O(n) + O(n) = O(2n), отбрасываем константу - O(n).
- **Память** - O(n). В памяти мы храним список всех категорий и список всех уникальных продуктов. В худшем случае количество категорий c равно количеству элементов n в sales, значит сложность O(n), и количество всех уникальных продуктов m, как и прежде, также может быть равно n - нет ни одного повторяющегося в худшем случае - сложность O(n). Всего O(n) + O(n) = O(2n), отбрасываем константу - O(n).
